# TokenTracking 0.6.0-preview.4

Fixes the unnecessary macOS permission request to **update or delete other apps** when TokenTracking launches Chrome.

The background refresher and login browser now skip Chrome’s temporary app-clone maintenance. TokenTracking does not need App Management permission; you can leave it off in System Settings → Privacy & Security → App Management. Chrome’s sandbox and signature checks remain enabled.

Both Mac downloads are Developer ID signed and notarized by Apple.

## Install or update

Choose `TokenTracking-0.6.0-preview.4-arm64.dmg` for Apple Silicon or `TokenTracking-0.6.0-preview.4-x64.dmg` for Intel. Requires macOS 13+ and Google Chrome; Node and the service are included.

Quit TokenTracking, replace it in Applications, then reopen it. History, browser logins and preferences are preserved.

Verify your download using the matching `.sha256` file:

```sh
shasum -a 256 -c TokenTracking-0.6.0-preview.4-arm64.dmg.sha256
```

## Verification

A controlled comparison with disposable Chrome profiles and a local-only page recorded an App Management request with app cloning enabled and none with it disabled. Both launches could read the page. The regression suite includes real Chrome fixtures and covers the shared launch settings used by refresh and login.

Live provider verification dates remain unchanged. Physical Intel Mac and fresh-Mac first-launch testing remain outstanding.
