# AGENTS.md: orientation for AI agents and new contributors

Read this first, then `docs/ARCHITECTURE.md`. The current state and next steps live in `docs/ROADMAP.md` and `CHANGELOG.md` → `[Unreleased]`.

## What this is
A personal, local-first tracker for AI **subscription** usage limits: Claude, Cursor (including Grok Bot), Gemini app and Muse, with Antigravity planned.
- **Menu bar app** (Swift): shows the most at-risk meter and starts and stops a zero-dependency **Node service** on 127.0.0.1:7878.
- **Node service:** every 15 minutes it launches a short-lived **headless Chrome** with a dedicated, logged-in profile, reads each provider from inside its own site, stores snapshots in SQLite, computes pacing and serves the dashboard.
- **No browser extension** since v0.5 (ADR-010).

## Hard constraints (don't violate without a new ADR and the user's sign-off)
- **No secrets.** Don't read cookies, the Keychain or CLI token files, and don't ask for API keys (ADR-002, SECURITY.md). The headless profile's logins stay inside Chrome; our code never reads them.
- **Nothing leaves the machine.** No telemetry, no third-party requests and no CDNs in the dashboard.
- **Zero dependencies** (ADR-003): Node built-ins only, and the Swift app is built with plain `swiftc`.
- **Read-only** against provider sites.
- **Invisible.** No visible windows or Dock activity during refresh (the user's explicit requirement).
- Never commit real captured payloads without redacting personal data (emails, names, org ids, the Cursor `?for=` user id).

## Layout
```
lib/                  shared, pure-ish: parse.js (meters, reset text), providers.js (parsers), scrape-dom.js (page reader, injected)
server/src/           Node service: index (timer, parent-PID watch), server (HTTP), db, pacing, status, cli
server/src/headless/  chrome.js = launch + CDP over pipe + browser identity; refresh.js = per-provider TASKS
server/public/        dashboard (vanilla JS; /?compact = menu bar panel view)
menubar/              macOS menu bar app (NSStatusItem + popover/WKWebView); scripts/build-menubar.sh builds it
scripts/              browser-login, refresh-once, seed-demo, build-menubar
test/                 node:test suites (headless.test.js drives real Chrome against fixtures)
docs/                 ARCHITECTURE, PROVIDERS, SECURITY, DECISIONS, ROADMAP
```

## Commands
```bash
npm test                                     # must pass before you finish
npm run refresh [-- muse]                    # one headless refresh now, prints per-service results
npm run browser-login [-- gemini]            # (user) log in once in the headless profile, then Cmd+Q
npm run build:menubar && open build/TokenTracking.app   # menu bar app (starts the service itself)
npm start                                    # service alone on :7878 (~/.tokentracking)
npm run status                               # terminal view
npm run demo && TOKENTRACKING_HOME=.tokentracking-demo TOKENTRACKING_PORT=7879 TOKENTRACKING_HEADLESS=0 npm start
```
`.claude/launch.json` has a `demo-dashboard` config (port 7879, headless off) for preview tools.

## Common tasks

**Fix or verify a provider.** Follow the "Verification loop" in `docs/PROVIDERS.md`.

**Debug a provider in headless.** The profile must not be in use (run it between refreshes):
```js
import { loadConfig } from './server/src/config.js';
import { launchChrome, openPage, browserIdentity } from './server/src/headless/chrome.js';
const { headless } = loadConfig();
const conn = await launchChrome({ chromePath: headless.chromePath, profileDir: headless.profileDir });
const page = await openPage(conn, { identity: await browserIdentity(conn) });
await page.goto('https://muse.ai/').catch(() => {});
console.log(await page.evaluate('location.href'));
// fs.writeFileSync('shot.png', await page.screenshot());
await page.close(); await conn.close();
```

**Add a provider.**
1. Add a task to `TASKS` in `server/src/headless/refresh.js` (`id`, `url`, `loggedOut`, `read`). Prefer in-page JSON (`page.evaluate(fetch…)`) and fall back to `readDom()`.
2. Put any parser in `lib/providers.js`, with a redacted-fixture test in `test/parse.test.js`.
3. Add a display name to `PROVIDER_NAMES` in `server/src/status.js` and to `PROVIDER_LABEL` in `server/public/app.js`.
4. Add the login URL in `scripts/browser-login.js`, and a row in `docs/PROVIDERS.md`.

**Change the meter shape or DB.**
1. Update `makeMeter` (`lib/parse.js`), `db.js` and the "Data model" section of ARCHITECTURE.md.
2. For the DB, bump `meta.schema_version` and migrate in `openDb`.

**Menu bar app.** Rebuild with `npm run build:menubar`, then quit and relaunch the app. The Swift source is one file. `BuildConfig.swift` (project and node paths) is generated by the build script.

## Conventions
- Plain ES modules, 2-space indent, single quotes, semicolons, small pure functions.
- Comments explain *why* and point to docs. Match the existing density.
- Pure logic goes in `lib/` or `server/src/pacing.js` so it's testable in Node.
- Every behavior change gets a test where practical, a CHANGELOG `[Unreleased]` entry, and a docs update in the same change.
- Significant design choices get a new ADR in `docs/DECISIONS.md`.

## Handoff checklist (end of every session)
- [ ] `npm test` passes.
- [ ] CHANGELOG `[Unreleased]` describes what changed.
- [ ] ROADMAP checkboxes updated; new findings added.
- [ ] PROVIDERS.md status table reflects what was verified, and when.
- [ ] Anything half-done is written down in ROADMAP under "Next" with enough context to resume.
